# 웹 음악방 신청

`/queue` 상단에서 곡명이나 가수를 입력하고 **검색**을 누르면 한 번의 요청으로 최대 10곡을 표시합니다. 제목·채널명·썸네일로 비교하고 **＋ 신청**을 누르세요. 같은 결과에서 여러 곡을 고를 수 있습니다. HTTPS YouTube 영상·재생목록 링크를 붙여 넣으면 신청 버튼이 링크 종류에 맞게 바뀝니다. 검색과 페이지 열기는 재생 명령을 보내지 않습니다. 신청곡은 기존 대기열 뒤에 들어가며 자동 배경음악보다 우선합니다.

기본은 꺼짐입니다. LAN 공유를 켜고 `lan.requests: {"enabled": true, "secret": "별도 생성한 32자 이상의 임의 비밀값"}`을 설정합니다. 이 비밀값은 관리자·재생기·Chat 키와 달라야 합니다. `search.enabled: true`와 YouTube API 키도 있어야 곡명 검색이 켜집니다. 키는 브라우저에 보내지 않습니다.

신청 전용 서명 쿠키(HttpOnly·SameSite=Strict, 12시간)와 메모리 CSRF 세션, 정확한 Origin/Host 검사로 요청을 보호합니다. 이 쿠키는 관리자·TV 제어 권한을 주지 않습니다. 일반 HTTP는 암호화되지 않으므로 신뢰하는 회사 LAN에서만 사용하며 인터넷에 포트를 노출하지 않습니다. 관리자/재생기 API는 기존 TLS·키 제한을 유지합니다.

공개 대기열에는 신청자를 표시하지 않습니다. 서버는 한도·중복 처리용 익명 식별자를 저장하므로 운영자에 대한 완전 익명이나 강한 사용자 인증은 아닙니다. 쿠키 삭제/브라우저 변경 시 새 방문자가 되며 같은 NAT의 IP 제한을 공유할 수 있습니다.

## 제한과 재시도

- 방문자별 대기곡 제한은 기존 `perUserLimit`을 따릅니다. 재생목록은 기존 최대 20곡/묶음·100곡 읽기 제한을 따릅니다.
- 곡·목록 신청은 IP별 분당 8회, 검색은 IP별 시간당 12회 및 해당 HTTP 리스너 전체 시간당 30회입니다. 검색 호출은 검색 버튼 또는 Enter로 실행하고 입력 중에는 호출하지 않습니다. 실제 YouTube 일일 쿼터를 보장하는 한도는 아니며 Chat·관리 검색도 같은 API 프로젝트 쿼터를 사용합니다. 검색이 제한되면 YouTube에서 직접 찾고 링크로 신청할 수 있습니다.
- 후보는 5분간 유효하며 최신 검색 후보만 선택됩니다. 다른 방문자의 후보를 선택할 수 없습니다.
- 같은 검색 결과에서 같은 곡을 여러 번 눌러도 한 번만 담깁니다. 링크 신청을 재시도할 때는 같은 요청 ID로 중복을 막습니다. 완료 결과는 기존 중복 기록 최대 5,000개 범위에서 보존합니다. 프로세스 재시작 시 CSRF 세션은 다시 연결하며 서명 비밀값이 유지되면 방문자 식별자는 이어집니다. 열린 검색 결과는 다시 검색해야 합니다.
- 입력은 최대 300자, 요청 본문은 8KB입니다. 재생 제어·취소·운영자 명령은 공개 API에서 받지 않습니다.

## Chat 바로가기

서버가 서명된 Apps Script 브리지에 공개 음악방 URL을 전달합니다. 새 Chat 메뉴와 `웹` 명령 응답에 링크가 표시됩니다. 관리자 토큰을 넣지 않습니다. Apps Script 저장 후 기존 웹 앱 배포를 새 버전으로 갱신해야 합니다. Google 카드 OpenLink는 HTTP를 HTTPS로 바꾸므로 메시지 본문의 일반 텍스트 링크를 사용합니다. 카드 앵커도 HTTPS로 변환되는 것을 실제 Chat에서 확인했으므로 카드에는 위쪽 주소를 누르라는 안내만 표시합니다.

## 검증

실제 loopback HTTP 테스트로 CSRF·출처 위조·잘못된 링크·다른 사용자 후보·오래된 후보·속도 제한·재시작 중복 보존과 관리자 API 격리를 확인합니다. 브라우저 시험은 외부 API와 TV에 연결되지 않은 별도 서버에서 검색·선택·영상 링크 신청을 확인합니다. 운영 화면에서는 검색만 하여 현재 음악을 보존합니다.
