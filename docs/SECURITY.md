# 보안 점검 및 운영 경계

2026-11-16 소스·브라우저 코드·Apps Script 인증 흐름·설정·저장·CI와 실행 구성을 점검했습니다. 운영 계정에 대한 침투시험이나 네트워크 전체 검사는 수행하지 않았습니다. 발견한 문제를 수정했으며 과거 침해 여부나 취약점이 전혀 없음을 보장하는 검사는 아닙니다.

| 항목 | 위험과 수정 | 검증 |
|---|---|---|
| 높음: LAN HTTP 제어 | 암호화되지 않은 연결에서 관리자/재생기 키가 노출될 수 있었습니다. 원격 제어는 실제 TLS 필수, localhost만 예외로 제한했습니다. forwarded 헤더는 신뢰하지 않습니다. | 실제 HTTPS 인증·불신 인증서/이름 불일치 거부, HTTP 제어 거부, 키 역할 분리 |
| 높음: 오래된 실행 환경 | 보안 패치 이전 Node로 실행되는 구성을 최신 보안 버전으로 교체했습니다. 지원 버전 미달은 시작을 거부합니다. | 버전 회귀 및 실제 CLI 실행 테스트 |
| 중간: 자원 고갈 | 요청/헤더/연결 시간·크기·개수 제한, 정적 파일 포함 IP별 속도 제한, 잘못된 Chat 명령 중복 기록과 알림 큐 상한을 보강했습니다. | 실제 HTTP 헤더 제한, 5,000개 중복 기록/500개 알림 상한 및 재시도 보존 |
| 중간: 저장·전달 | 백업을 0600 새 파일로 원자 교체합니다. API 키는 URL 대신 헤더로 전달하며 리디렉션을 금지합니다. | 이전에 넓은 권한의 백업도 교체 시 축소, 저장 회귀 테스트 |
| 방어 보강 | Host·Origin 검사, 프레임/폼/권한 정책, 관리 화면 연결 해제·키 삭제, 원격 HTTP의 캐시된 키 전송 차단을 적용했습니다. | 실제 TLS/HTTP와 브라우저 코드 회귀 테스트 |
| 공급망 | CI 액션을 검증한 commit SHA로 고정하고 체크아웃 인증정보 저장을 끕니다. 런타임 npm 의존성은 없습니다. | Linux·Windows CI 및 공개 대상 비밀 검사 |

검색은 키 존재 여부와 별개로 `search.enabled: true`에서만 켭니다. 독립 검색 검증 이전에 키 저장만으로 운영 검색을 활성화하지 않습니다.

## 운영자가 알아야 할 사항

- 기존 HTTP로 사용한 제어 키는 예방적으로 교체해야 합니다. 교체 후 재시작하면 기존 영구 키와 메모리 내 재생 키는 무효화됩니다. 키는 설정에만 두고 URL·채팅·공개 저장소에 넣지 않습니다.
- LAN 관리에는 접속 IP/이름이 SAN에 포함되고 이용 기기가 신뢰하는 인증서를 사용합니다. 회사 발급 인증서를 권장합니다. 자체 서명 인증서는 수동 확인과 신뢰가 필요하며 프로그램이 OS 신뢰를 바꾸지 않습니다. 개인키는 공유하지 않습니다.
- 공개 플리 조회 API는 읽기 전용이며 선택적으로 켜는 웹 신청 API는 검색·곡 추가만 허용합니다. HTTP에서는 같은 네트워크에서 곡 제목을 볼 수 있고 전송 내용의 무결성이 보장되지 않습니다. 민감한 제목이라면 공유를 끄거나 신뢰된 HTTPS 주소를 사용합니다. 인터넷으로 포트를 공개하지 않습니다.
- 관리 키는 공유된 운영 권한입니다. 관리자별 감사·권한 회수·MFA는 제공하지 않습니다. 운영자 수를 제한하고 퇴사/권한 회수 때 키를 교체합니다. 연결 해제는 해당 탭의 키만 지우며 키 자체를 폐기하지 않습니다.
- Chat 비공개 신청은 참여자 간 노출을 줄입니다. 봇 운영자·Google·Workspace 관리자에 대한 완전 익명은 아닙니다.
- YouTube TV 비공식 연결 프로토콜, 외부 재생목록 HTML, Google/YouTube 서비스의 변경과 재생 제한은 별도 운영 위험입니다. 실제 TV 재생 증명은 현장 관측이 필요합니다.
- 정적 검토와 테스트는 과거 도청·침해 부재를 증명하지 않습니다. 설정·데이터·백업·개인키는 공개하지 말고 로컬 접근 권한도 제한합니다. macOS/Linux의 0600과 달리 Windows는 별도 ACL 정책을 확인해야 합니다.
