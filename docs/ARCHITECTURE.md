# 설계와 실패 시 동작

## 실행 위치

GitHub: 소스와 자동 테스트. 로컬 컴퓨터: Google worker, HTTP UI, 저장소, 기기 제어. 재생: TV 기본 앱 또는 브라우저. Pub/Sub는 인터넷에서 컴퓨터로 접속하지 않고 컴퓨터가 외부로 연결하게 합니다.

## 상태

`queued → dispatching → sent_unconfirmed → playing → ended`

- 브라우저만 재생 이벤트로 `playing`, `ended`를 보고하고 다음 곡으로 이동합니다.
- 기본 앱은 명령 수락과 실제 재생을 구분합니다. 자동 종료 감지나 곡 길이 기반 타이머는 없습니다.
- `blocked`: 브라우저 자동재생 차단. 현장 버튼으로 재생.
- `error`: 기기 오류 또는 영상 오류. 자동 재전송하지 않고 운영자가 확인.
- `recovery_required`: 서버 재시작/재생기 교체/긴 연결 중단. 오래된 곡을 임의로 다시 재생하지 않음.
- `expired`: 4시간 지난 대기곡을 보관 기록으로 이동.

전송 도중 네트워크가 끊기면 기기가 이미 명령을 받았을 수 있습니다. 따라서 불확실한 요청을 무작정 반복하지 않습니다. `재시도`는 운영자가 기존 재생을 확인한 후 선택해야 합니다.

## 저장 / 일관성

프로세스 안의 변경은 하나의 비동기 직렬 큐에서 수행합니다. 파일은 임시 파일 후 rename으로 교체합니다. 현재 곡을 전송 직전에 저장하고 재시작 시 복구 상태로 둡니다. 물리적 디스크 장애까지 보장하는 DB는 아닙니다. 동시 프로세스, 다중 노트북 운영, 분산 잠금은 지원하지 않습니다.

Google 이벤트 처리는 message resource name(없으면 Pub/Sub ID)으로 중복을 막습니다. 처리 결과와 응답 outbox를 먼저 저장한 후 ACK합니다. Chat API에는 outbox의 고정 client message ID를 전달합니다. 응답 성공 직후 프로세스가 죽어도 재시도 시 409를 처리하고 노래를 중복 신청하지 않습니다. 영구적인 Chat 권한 오류는 운영자가 고쳐야 합니다.

## 접속 / 인증

- Google: 서비스 계정 RS256 JWT로 액세스 토큰 발급. scope별 캐시, 자동 만료 갱신. 비밀 키는 로컬 파일.
- Pub/Sub topic 게시 권한은 Chat 서비스 주체에게만 부여. 노트북 계정은 해당 subscription 수신 권한.
- Chat: 허용된 space만 처리. 일반 채팅 전체를 구독하는 Workspace Events 설계가 아니라 앱 멘션/상호작용을 수신.
- 로컬 HTTP API: 관리자/재생기 bearer 토큰 분리, 외부 Origin 차단, CORS 미허용, 8KiB 요청 제한, IP별 분당 180회 제한.
- 토큰은 URL로 전달하지 않음. 관리 UI는 sessionStorage, 재생 UI는 메모리에만 보관.
- 기본은 127.0.0.1. LAN HTTP는 암호화되지 않으므로 신뢰된 망 또는 HTTPS 프록시 필요.
- TV TLS: 등록된 인증서 지문과 한 연결의 peer certificate를 대조한 뒤 원격 명령 전송. 전역 TLS 무효화 환경변수 없음.

## 아직 하지 않은 것

- 모든 실제 모델의 호환성 검증, 앱 자동 설치, 자동 펌웨어 변경.
- Cast/YouTube Lounge의 비공식 세션 자동화, 음원 추출, 광고 제거.
- 기본 앱의 영상 ID/종료 상태 검증 및 자동 대기열.
- Android TV Remote 프로토콜 직접 구현(현재 HA REST 연동).
- 검색 결과 선택 카드, 운영자 UI 편집기, 멀티룸, 사용자별 신청 제한, 자동 재생 알림.
- Google Workspace 실제 등록, API 키 생성, 실제 TV 접속. 사용자의 계정/기기가 필요.

브라우저 단일 화면 대기열과 기본 앱 한 곡 실행을 검증 가능한 작은 범위로 구현한 MVP입니다. 기본 앱에서 완전한 Discord형 대기열을 운영하려면 실제 모델에서 재생 상태를 얻는 경로를 추가해야 합니다.
