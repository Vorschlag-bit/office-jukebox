# 설계와 실패 시 동작

## 실행 위치

GitHub: 소스와 자동 테스트. 로컬 컴퓨터: Google worker, HTTP UI, 저장소, 기기 제어. 재생: TV 기본 앱 또는 브라우저. Apps Script는 Chat 요청을 짧게 저장하고, 노트북이 기본 5초 간격으로 외부 HTTPS 연결을 열어 가져갑니다. 비용·배포·순서는 [Apps Script 가이드](APPS-SCRIPT.md)에 있습니다.

## 상태

`queued → dispatching → sent_unconfirmed → playing → ended`

- 브라우저만 재생 이벤트로 `playing`, `ended`를 보고하고 다음 곡으로 이동합니다.
- TV 코드 어댑터는 실제 영상 ID와 재생 nonce(CPN)가 일치하는 playing/ended 이벤트를 사용합니다. 기존 제조사별 앱 실행은 미확인 상태로 남습니다. 곡 길이 기반 타이머는 없습니다.
- `blocked`: 브라우저 자동재생 차단. 현장 버튼으로 재생.
- `error`: 기기 오류 또는 영상 오류. 자동 재전송하지 않고 운영자가 확인.
- `recovery_required`: 서버 재시작/재생기 교체/긴 연결 중단. 오래된 곡을 임의로 다시 재생하지 않음.
- `expired`: 4시간 지난 대기곡을 보관 기록으로 이동.

전송 도중 네트워크가 끊기면 기기가 이미 명령을 받았을 수 있습니다. 따라서 불확실한 요청을 무작정 반복하지 않습니다. `재시도`는 운영자가 기존 재생을 확인한 후 선택해야 합니다.

## 저장 / 일관성

프로세스 안의 변경은 하나의 비동기 직렬 큐에서 수행합니다. 파일은 고유 임시 파일에 쓰고 fsync 후 rename으로 교체하며, 직전 파일을 백업합니다. 현재 곡을 전송 직전에 저장하고 재시작 시 복구 상태로 둡니다. 프로세스 잠금으로 같은 저장소의 중복 실행을 거부합니다. 물리적 디스크 장애나 분산 운영을 보장하는 DB는 아닙니다.

Google 메시지 resource name의 해시를 중계/로컬에서 중복 검사합니다. 5분 TTL, 30초 임대 후 처리하며 로컬 저장을 마친 뒤 ACK합니다. 결과 HTTP 요청은 엔진 잠금 밖에서 실행하고 일시 오류는 백오프합니다. 잘못된 수신자는 격리합니다. 중계 결과는 사용자+스페이스별 최신 1건으로 저장하고 `결과` 명령으로 조회합니다.

ScriptProperties는 여러 속성의 트랜잭션을 제공하지 않습니다. 저장 사이 실행 중단/할당량 오류는 부분 변경을 만들 수 있습니다. 최근 접수 100개·처리 5,000개·결과 영수증 100개의 중복 억제와 명시적인 복구를 사용하며 전체 경로의 exactly-once를 보장하지 않습니다. 중계 결과는 최대 50명/24시간이고 자발적 Chat 푸시는 없습니다. 기존 Pub/Sub 모듈은 회귀 테스트용으로 남아 있지만 실행 진입점에서 호출하지 않으며 이전 활성 설정을 거부합니다.

## 접속 / 인증

- Google: HMAC-SHA256 서명, 60초 시간창, nonce 임시 캐시, 단일 worker 임대. 비밀은 로컬 설정/ScriptProperties. 추가 OAuth 범위 없음.
- 웹 앱은 소유자 실행·Anyone 접근이 필요. 조직 정책이 허용하지 않으면 이 경로 사용 불가. 결제 계정 미연결은 콘솔에서 별도 확인.
- Chat: 허용된 space만 처리. 일반 채팅 전체를 구독하는 Workspace Events 설계가 아니라 앱 멘션/상호작용을 수신.
- 로컬 HTTP API: 관리자/재생기 bearer 토큰 분리, 외부 Origin 차단, CORS 미허용, 8KiB 요청 제한, IP별 분당 180회 제한.
- 토큰은 URL로 전달하지 않음. 관리 UI는 sessionStorage, 재생 UI는 메모리에만 보관.
- 기본은 127.0.0.1. LAN HTTP는 암호화되지 않으므로 신뢰된 망 또는 HTTPS 프록시 필요.
- TV TLS: 등록된 지문과 TLS peer certificate를 먼저 대조하고, 일치한 소켓만 HTTP 클라이언트에 넘깁니다. 토큰이 HTTP 헤더/URL로 나가기 전에 확인합니다. 전역 TLS 무효화 환경변수 없음.
- TV 코드: 등록한 화면의 Lounge 토큰만 사용. 고정 YouTube HTTPS endpoint, 브라우저 쿠키/인증 DB 접근 없음. 비공식 프로토콜의 변경 위험 존재.

## 아직 하지 않은 것

- 모든 실제 모델의 호환성 검증, 앱 자동 설치, 자동 펌웨어 변경.
- Cast 프로토콜 자체 구현, 자동 DIAL/SSDP 기기 탐색, 음원 추출, 광고 제거.
- 실제 TV 모델의 Lounge 이벤트 호환성 검증 및 전원/앱 자동 시작 보장.
- Android TV Remote 프로토콜 직접 구현(현재 HA REST 연동).
- Google Chat의 선택 카드(현재 텍스트 번호 선택), 멀티룸, 운영자 UI 설정 편집기.
- Google Workspace 실제 등록, API 키 생성, 실제 TV 접속. 사용자의 계정/기기가 필요.

브라우저 대기열과 TV 코드 기반 조건부 자동 대기열을 구현했습니다. 실사용 완료 판정은 계정 연결과 물리적 화면에서의 검증 이후에 가능합니다. 대체 경로로의 자동 전환은 하지 않습니다. 기존 기기가 이미 재생 중일 수 있으므로 운영자가 실제 정지를 확인한 뒤 전환해야 합니다.
