# 운영과 복구

## 처음 시작

1. Node 24 이상을 준비하고 `node src/main.js init` 실행.
2. 생성된 로컬 설정에서 재생 방식을 선택. 빠른 확인은 browser + 노트북 HDMI.
3. 기본 YouTube 앱은 `pair-tv`를 사용해 본인 화면과 연결하고 현장 확인.
4. `node src/main.js doctor`로 설정 검사.
5. Google 설정을 준비했다면 `node src/main.js check-google`로 구독과 허용 공간 접근 검사. 이 검사는 읽기만 수행.
6. `node src/main.js` 또는 `node bin/run.js`로 실행.
7. [완료 조건](ACCEPTANCE.md)의 실제 테스트를 실시.

설정의 `perUserLimit` 기본값은 5, 전체 `maxQueue`는 50, 대기곡 만료는 4시간입니다. 숫자 0의 perUserLimit는 사용자별 제한을 해제합니다. YouTube API 키는 YouTube Data API로 제한하고, 서비스 계정에는 필요한 Pub/Sub subscription 권한만 줍니다. 비밀번호, 키, 쿠키를 코드에 넣지 않습니다.

## 매일 확인

- 실제 화면과 소리, 관리 화면의 현재 상태가 일치하는지 확인합니다.
- `/api/diagnostics`는 관리자 토큰으로만 조회됩니다. Google 연결 상태와 오류 코드, 알림 대기/실패 개수, 어댑터의 기능 상태만 반환합니다.
- `sent_unconfirmed`는 성공이 아닙니다. 기본 45초 후에도 재생 이벤트가 없으면 오류로 표시합니다.
- 원격 서비스 장애 때도 로컬 관리 화면으로 대기열을 조회·정지할 수 있어야 합니다.
- JSON 파일에는 신청 사용자 ID와 영상 기록이 있습니다. `data/`를 비공개로 관리합니다.

## 오류별 복구

| 상태 | 동작 |
|---|---|
| `blocked` | 재생 화면의 소리 있는 재생 허용 버튼 사용 |
| `error` | 화면과 오류를 확인하고 `재시도` 또는 `다음` |
| `recovery_required` | 실제 재생을 먼저 확인. 자동 재전송하지 않으므로 운영자가 `재시도`/`다음` 선택 |
| 3개 영상 연속 재생 불가 | 자동 대기열 일시정지. URL/환경을 확인하고 `계속` |
| `ALREADY_RUNNING` | 같은 저장소를 사용하는 기존 서버를 종료. 다른 프로세스를 임의로 종료하지 않음 |
| `LOCK` | 손상 잠금 파일. 서버가 실행 중이지 않음을 확인한 뒤 별도 보관 후 재시작 |
| 저장소 손상 | 서버 종료 후 `node src/main.js restore-state` 실행 |
| Google 401 | 서비스 계정/키/시간 설정 확인. 토큰 캐시는 만료/401 시 갱신 |
| Google 403/404 | API 활성화, 앱 프로젝트, 서비스 계정 IAM, 앱의 공간 참여, 허용 space ID 확인 |
| Google 429/5xx | 지수 백오프 재시도. 로컬 제어와 Pub/Sub 수신은 계속 |

`restore-state`는 `state.json.bak`를 검증하고 원래 파일을 `state.json.damaged-타임스탬프.json`으로 보존한 뒤 복원합니다. 백업보다 최근의 신청/알림은 복원되지 않을 수 있습니다. 서버 재시작 후 현재 곡은 복구 대기 상태입니다.

## 알림 실패 재전송

영구 오류로 격리된 알림은 원인을 해결한 뒤 관리자 API로 다시 넣을 수 있습니다.

```text
POST /api/retry-notifications
Authorization: Bearer <adminToken>
Content-Type: application/json

{}
```

원래 메시지 ID를 유지하므로 이미 전송된 응답은 409로 안전하게 정리됩니다. 전송 실패 기록은 최근 100개로 제한되며 이를 넘은 오래된 알림은 복구할 수 없습니다. 자동 장애 이력 보관 시스템은 아닙니다.

## 재생 경로 전환

1. 실제 기기의 재생을 멈춥니다. 네트워크 오류 때는 이미 재생 중일 수 있습니다.
2. 서버를 종료합니다.
3. `node src/main.js use-browser` 또는 `node src/main.js use-previous` 실행.
4. 서버를 시작합니다. 브라우저 모드라면 `/player`를 열고 새 토큰 연결 및 재생 허용.
5. 기존 곡을 자동으로 중복 재생하지 않도록 복구 대기에서 `다음` 또는 `재시도` 선택.

자동으로 여러 기기에 동시에 재생하거나 장애 때 다른 경로를 몰래 시작하지 않습니다.

## 프로세스 감독

`node bin/run.js` / `run.cmd`는 이 프로젝트가 만든 자식 프로세스만 관리합니다. 비정상 종료 시 지수 간격으로 재시작하며 10분 동안 5번 실패하면 중단합니다. Ctrl+C는 감독기와 자식 서버를 종료합니다. OS 서비스, 방화벽, 절전 설정, 시작 프로그램을 자동 변경하지 않습니다. 전원 차단·수면 상태·물리적 네트워크 장애는 사용 환경에서 관리해야 합니다.
