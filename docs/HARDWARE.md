## 공통

- [ ] 잘못된 URL과 권한 없는 정지 요청 거부

## 기본 앱

- [ ] `probe` TCP 접근 확인 (성공해도 재생 지원을 뜻하지 않음)
- [ ] TLS 사용 시 기기 인증서 지문 대조
- [ ] 기기에서 페어링 승인, 재실행 후 토큰/client key 재사용
- [ ] 영상 A의 URL로 **해당 영상** 재생 (앱 홈만 열리는 것과 구분)
- [ ] 영상 B의 URL로 다른 영상 전환
- [ ] 정지 명령이 실제로 작동
- [ ] 기기 전원 꺼짐/연결 거부 시 앱이 성공으로 표시하지 않음
- [ ] 기기 절전/재부팅 후 재연결
- [ ] 광고 후, 연령/지역/로그인 제한 영상에서 동작 확인
- [ ] 수동 `다음`으로 다음 신청곡 실행

기본 앱이 앱 홈까지만 열리면 `experimentalVideoLaunch`를 끄고 브라우저/HDMI 대안을 사용합니다. 모델·펌웨어·앱 ID·증상을 개인정보 없이 기록하면 어댑터를 조정할 수 있습니다.

## 브라우저 / HDMI

- [ ] `/player` 페이지 로드와 토큰 입력
- [ ] 공식 유튜브 플레이어 로드
- [ ] 소리 있는 재생 허용 버튼 동작
- [ ] 2곡 연속 신청 후 종료 이벤트로 정확히 한 번 다음 곡 이동
- [ ] 재생 중 다음/정지 명령 동작
- [ ] 두 번째 탭이 기존 재생기를 뺏지 못함
- [ ] 새로고침/서버 재시작 후 `recovery_required` 표시, 운영자 복구
- [ ] 1시간 이상 연속 재생: 메모리 부족, 자동 종료, 절전 확인
